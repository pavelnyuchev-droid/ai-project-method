# Модуль «ИИ-шаги» (флажок ИИ)

Модуль методики 3.0. Читается, если в паспорте проекта стоит флажок **ИИ** (в решении есть LLM, распознавание или модель).
Связано: [Ядро](<../README.md>) · [Паспорт ИИ-шага](<../templates/Паспорт-ИИ-шага.md>) · [Чек-лист защиты](<../templates/Защита-ИИ-шага.md>)

**Термины.** ИИ-шаг — шаг процесса, где решает или готовит модель. Агентный конвейер — LLM на заранее заданном графе шагов (наши решения на n8n).
Агент — система, которая сама строит план и действует без согласования шагов (ступень 4 и выше). Клиенту пишем «ИИ-шаг», словом «агент» не злоупотребляем.

## Этап 3 — ворота и паспорт
**Ворота** для каждого шага, где рассматривается ИИ, по порядку: можно ли шаг убрать → хватит ли регламента → хватит ли n8n без LLM → ИИ готовит, человек решает →
ИИ действует с подтверждением → ИИ действует в лимитах. ИИ берётся, только если выигрывает у варианта без него. Вопросы: где деньги («ускорение» — не эффект);
процесс описан и замерен; нужен ли ИИ; кто отвечает за результат; цена ошибки и обратимость.

**Паспорт** на каждый ИИ-шаг ([шаблон](<../templates/Паспорт-ИИ-шага.md>)):
- **ступень автономии**: 0 наблюдает · 1 советует · 2 готовит черновик · 3 действует с подтверждением человека · 4 действует в лимитах по правилам · 5 сам меняет правила под аудитом;
  **деньги, медицина, юридически значимое — не выше 3**; ступень повышается только по замеру, без перепрыгивания;
- **карта проверок**: где, кто, что блокируется без проверки, кому эскалация. Человек подтверждает **понимание задачи и результат, а не алгоритм**;
- **ограничители** на входе и выходе в n8n: схема ответа, диапазоны, белый список действий, права в БД; **технические параметры (ключи, ID записей, chat_id) подставляет n8n — модель их не видит**;
- **безопасное состояние**: при низкой уверенности, ошибке, выходе за рамки — «на ручной разбор» и уведомление; ответ со ссылкой на источник;
- **версия**: модель, промпт, параметры вызова; смена любого — изменение с прогоном;
- **данные**: только идентификаторы (модуль ПД); **память**: что хранится, где (отдельно от воркфлоу), сколько;
- **защита**: [чек-лист](<../templates/Защита-ИИ-шага.md>) — отметки «применимо / н/п».

**«Вероятность отказа ИИ = 1»:** для шагов со значимыми последствиями проектируем так, будто модель уже ошиблась — доверие держится на архитектуре, не на промпте.

**Тестовый набор — до первой версии промпта.** Размер по профилю: S — 15–20, M — 30, L — 50 случаев (обезличенные реальные + синтетические):
способности; регрессия (порог — 95 %, ниже — назад в «в работе»); эскалация (5–10 неоднозначных случаев, верно — «к человеку»);
для внешнего ввода — поведение и 10–20 атак через промпт (модуль [Клиентский канал](<Клиентский-канал.md>)).

## Этап 4 — MVP
Только ступени не выше 3; прогон набора после каждой правки; **параллельный прогон** с ручным процессом; где ИИ даёт варианты — слепое сравнение «лучший из трёх».

## Этап 5 — Платформа
- **Стоп-кран:** лимит шагов и повторов на выполнение (против зацикливания); автоматический перевод шага «на ручной разбор», если доля ручных правок выше порога.
- Лимит токенов или ₽ на выполнение; маршрут «простое — дешёвая модель, сложное — сильная» по прогону.
- Код, сгенерированный ИИ, — только на тестовом стенде до ревью.

## Этапы 6–7 — Сдача и Сопровождение
- Приёмка набора на данных заказчика (обезличенных).
- **Дрейф:** доля ручных правок выхода ИИ — рабочий коридор 10–25 %; больше 40 % — шаг слабый (разбор, понижение ступени); меньше 5 % — проверить, не стала ли проверка формальной (выборочная проверка).
- Риски ИИ в `РИСКИ.md`: данные; инъекции через «обогащающий канал» (документы, веб, объявления); ложный результат одного бота для другого; неверный вывод; непрозрачность; закон.
