# Чек-лист защиты ИИ-шага

Один список вместо разрозненных мер (МИФИ, Сбер — AI-Disrupt PDLC и гайд по мультиагентным системам, CANUKUS). В паспорте — отметка «применимо / н/п» по каждому пункту.

1. В модель уходят только идентификаторы, без ПД.
2. В системном промпте нет сведений о среде: ключей, имён баз, ролей, структуры прав.
3. Технические параметры (ключи, ID записей, chat_id) подставляет n8n, модель их не видит.
4. Фильтр входа: инъекции, подмена роли, просьбы раскрыть инструкции.
5. Валидация выхода по схеме (JSON), диапазоны, белый список действий.
6. Доступ к данным — по шаблонам или параметризованным запросам под ролью только для чтения; свободный SQL от модели — нет.
7. Изоляция контекста между клиентами и между проектами; один уровень конфиденциальности на связку ботов.
8. Подтверждение человеком исходящих писем, распоряжений и юридически значимых ответов.
9. Лимиты: шаги, повторы, токены или ₽, сообщения, частота запросов.
10. Ответ со ссылкой на источник; при неуверенности — «к человеку».
11. Версия модели, промпта и параметров зафиксирована; смена — с прогоном.
12. Пометка «отвечает ИИ» для внешних людей; маркировка сгенерированного, где нужно.
13. Журнал вызовов без ПД; мониторинг аномалий (зацикливание, слишком длинный план, всплеск вызовов).
14. Код, сгенерированный ИИ, — только на тестовом стенде до ревью.
15. Тесты атак (для внешнего ввода): 10–20 случаев, допуск — 0 успешных.
