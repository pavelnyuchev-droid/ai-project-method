# Этап 4. MVP

Карточка этапа методики 3.0. Читается, пока в паспорте проекта «Этап: 4».
Связано: [Ядро](<../README.md>) · [Этап 3](<3-To-Be-и-ТЗ.md>) · [Этап 5](<5-Платформа.md>)

**Цель:** минимальная рабочая версия, которая проходит сквозной сценарий на реальных (обезличенных) данных и проверена по критериям ТЗ.

## Шаги
1. Работа короткими итерациями с показом заказчику; каждая итерация — «шаг → проверка».
2. Разработка по требованиям: в коммите или описании изменения — ID требования. Правка поведения — сначала требование или паспорт, потом n8n.
3. **Стандарты ремесла n8n** — правила ремесла команды для n8n: повторный запуск без дублей, понятные ошибки, сквозной номер заявки или сделки во всех узлах и логах,
   секреты только в учётных данных n8n.
4. **Прогон** по критериям приёмки: отчёт прогона с номером выполнения n8n — доказательство «сделано».
5. Показ заказчику → замечания → изменения только через запрос, если они вне ТЗ.

## Модули на этом этапе
ИИ — только ступени не выше 3, прогон тестового набора, параллельный прогон с ручным процессом; ПД — проверка, что в LLM уходят только идентификаторы;
Канал — «отвечает ИИ» и «связаться с человеком»; Деньги — подтверждение денежных шагов человеком, аудит дублей.

## Критерий выхода
Сквозной прогон на обезличенных или тестовых данных прошёл по всем обязательным требованиям (отчёт прогона); заказчик посмотрел MVP. Запись `решение` «этап 4 → 5».

## Не делать
Не подключать боевые данные и деньги на MVP. Не наращивать функции сверх ТЗ «заодно».
