# Методика ведения проектов с ИИ: знания копятся, успех доказывается

Практическая методика для команды, которая ведёт проекты вместе с нейросетями.
Подходит для **любой** модели и любого инструмента: ChatGPT, Claude, Gemini, DeepSeek, GigaChat,
YandexGPT, Qwen; агенты с доступом к файлам — Codex, Claude Code, Cursor, Gemini CLI, Qwen Code,
Aider, Jules. Для работы нужны только папка с текстовыми файлами Markdown и дисциплина.

Автор — Павел Нючев, AI Consulting ([prostodelai.store](https://prostodelai.store)). Версия 1.0 от 29.09.2026.
Лицензия [CC BY 4.0](LICENSE): пользуйтесь и меняйте, указывая источник.

---

## 1. Идея в трёх фразах

1. **Знания раскладываются один раз — когда источник поступает, а не ищутся заново при каждом вопросе.**
   Новая стенограмма встречи, письмо, документ сразу разносятся по живым страницам проекта.
   Дальше нейросеть читает короткие страницы, а не перерывает сотни сырых файлов.
2. **Токены и время уходят на ведение знаний, а не на повторный поиск.** Каждый новый источник
   делает проект богаче. Без методики каждая сессия начинается с нуля.
3. **«Сделано» пишется только с доказательством.** Нейросети охотно рапортуют об успехе.
   Отметка ставится, когда есть проверка, а не обещание.

## 3. Три слоя проекта

```
Проект/
├── Источники/            ← СЛОЙ 1: входящее как есть. Нейросеть только читает.
│   └── _резюме/          ←   резюме каждого источника
├── INDEX.md              ← оглавление: его читают первым
├── ЖУРНАЛ.md             ← хронология: только дописывается
├── СТАТУС.md             ┐
├── ПЛАН.md               │
├── РЕШЕНИЯ.md            │ СЛОЙ 2: живые страницы.
├── ВОПРОСЫ.md            │ Пишет нейросеть, читает и правит человек.
├── ГЛОССАРИЙ.md          │
├── <рабочие папки>/      ┘
└── AGENTS.md             ← СЛОЙ 3: правила проекта для любых агентов
```

- **Источники** — стенограммы, записи встреч, письма, документы заказчика, выгрузки, скачанные
  материалы. Имя файла — `Что_ГГГГ-ММ-ДД.расширение`. **Нейросеть их не правит, не переименовывает
  и не удаляет.** Это «исходный код» знаний.
- **Живые страницы** — всё, что выведено из источников: где мы сейчас, что решено и почему, что не
  решено, куда идём, что значат термины. Это «скомпилированный» проект.
- **Правила** — файл, который превращает нейросеть из собеседника в аккуратного ведущего проекта.
  Шаблон — [templates/AGENTS.md](templates/AGENTS.md).

Готовые заготовки всех файлов — в папке [templates/](templates). Скопируйте её в новый проект.

## 4. Два служебных файла

**`INDEX.md` — оглавление.** Каждая живая страница и каждый источник одной строкой: что это
и когда нужно. Нейросеть читает его первым и открывает только нужное. Обновляется при каждом приёме.

**`ЖУРНАЛ.md` — хронология.** Только дописывается, новые записи внизу, старое не правится.
Одна строка — одно событие:

```
## [2026-09-29] приём | Стенограмма встречи 12.09 → СТАТУС, РЕШЕНИЯ Р-14, ВОПРОСЫ В-22
## [2026-09-30] решение | Р-15: отчёт по сделкам раз в неделю → РЕШЕНИЯ, ПЛАН
## [2026-10-05] сверка | 3 противоречия, 2 устаревших пункта → вопросы В-23…В-25
```

Типы записей: `приём`, `вопрос`, `решение`, `сдача`, `сверка`, `инцидент`, `сессия`.

## 5. Три операции

### Приём — поступил новый источник

1. Положить файл в `Источники/`.
2. Нейросеть пишет резюме в `Источники/_резюме/`.
3. Разносит новое по живым страницам: решения, вопросы, статус, план, глоссарий.
4. **Отмечает противоречия со старым** и выносит их вопросом человеку, а не исправляет молча.
5. Обновляет `INDEX.md` и дописывает строку в `ЖУРНАЛ.md`.

После приёма большой источник больше не читается целиком — работают с его резюме.
Готовый промпт — [prompts/1-приём.md](prompts/1-приём.md).

### Вопрос — нужно что-то узнать или решить

Ответ строится по живым страницам **со ссылками** на них. Если ответ ценный (сравнение, расчёт,
разбор), он сохраняется новой страницей и попадает в `INDEX.md`. Так знание копится, а не теряется в чате.
Промпт — [prompts/2-вопрос.md](prompts/2-вопрос.md).

### Сверка — раз в неделю

Нейросеть проверяет проект и **пишет отчёт, ничего не исправляя**:
- противоречия между страницами;
- устаревшие утверждения;
- страницы, на которые никто не ссылается;
- битые ссылки;
- «сделано» без доказательства;
- вопросы без движения больше двух недель.

Правки вносятся после одобрения человеком. Промпт — [prompts/3-сверка.md](prompts/3-сверка.md).

## 6. Честный статус

У каждого пункта плана четыре состояния: **план → в работе → сделано → принято**.

| Отметка | Когда ставится |
|---|---|
| **сделано** | есть ссылка на доказательство: скриншот, номер выполнения, файл результата, отчёт прогона, коммит. Нет ссылки — пункт остаётся «в работе» |
| **принято** | заказчик подтвердил: кто, когда, ссылка на письмо или стенограмму |

- **Регресс снимает отметку.** Сломалось сделанное — пункт возвращается в «в работе», в журнал
  пишется `инцидент`.
- В `СТАТУС.md` видны две цифры: «сделано у нас» и «принято заказчиком». Это разные вещи.
- Заглушки, пропущенные проверки и непроверенные предположения называются прямо. «Должно работать» —
  не статус.

## 7. Четыре правила исполнителя

Для любых агентов и для людей:

1. **Думать до работы.** Допущения проговариваются. Если задачу можно понять по-разному,
   показать варианты, а не выбирать молча. Непонятно — остановиться и спросить.
2. **Сначала простота.** Минимум, который решает задачу. Никаких функций «на будущее».
3. **Хирургические правки.** Трогать только то, чего требует задача. Соседнее не «улучшать»;
   замеченную постороннюю проблему назвать, но не чинить.
4. **Проверяемая цель.** До начала работы задача переписывается в критерии успеха. План пишется
   как «шаг → проверка».

## 8. Как вести сессию

**Начало.** Нейросеть читает `INDEX.md`, `СТАТУС.md` и последние 20 записей `ЖУРНАЛ.md` — не всю папку.
Затем даёт снимок состояния в пять строк: что изменилось, что ждёт ответа, что мешает.

**Работа.**
- Спорное решается **вопросами по одному.** В вопросе есть варианты, рекомендация и её цена.
- Ответ записывается **сразу**: решение с причиной — в `РЕШЕНИЯ.md`, ответ — в `ВОПРОСЫ.md`.
  Следующий вопрос — только после записи. Оборванная сессия не должна стоить принятых решений.
- **Каждый созданный или изменённый файл называется полным путём.** Иначе человек ищет его сам.

**Конец.** Записи в `ЖУРНАЛ.md`, обновлённый `СТАТУС.md`, при необходимости — резюме сессии.

Промпты — [prompts/0-начало-сессии.md](prompts/0-начало-сессии.md) и [prompts/4-конец-сессии.md](prompts/4-конец-сессии.md).

**Заказчику** — не открытый вопрос, а подтверждение: «Сделано так. Согласны — да или нет?
Если нет — как нужно?» Одно слово в ответ вместо сочинения с нуля.

## 9. Как работать с разными нейросетями

### А. Агент с доступом к файлам: Codex, Claude Code, Cursor, Gemini CLI, Qwen Code, Aider, Jules

1. Положите [templates/AGENTS.md](templates/AGENTS.md) в корень проекта. Codex, Cursor, Jules,
   Copilot и многие другие читают `AGENTS.md` сами.
2. Для инструментов со своим именем файла сделайте файл-указатель с одной строкой
   «Правила проекта — в AGENTS.md, прочитай его первым»:
   - Claude Code — `CLAUDE.md` (можно написать `@AGENTS.md`);
   - Gemini CLI — `GEMINI.md`;
   - Cursor — `.cursor/rules`.
3. Дальше работайте промптами из [prompts/](prompts). Агент сам читает оглавление и сам пишет журнал.

### Б. Чат без доступа к файлам: ChatGPT, Claude.ai, Gemini, DeepSeek, GigaChat, YandexGPT, Алиса

1. Заведите в сервисе «проект» — так он называется в ChatGPT и Claude; в Gemini это Gems;
   в других сервисах — постоянная инструкция. В инструкцию вставьте текст [templates/AGENTS.md](templates/AGENTS.md).
2. В начале сессии загрузите три файла: `INDEX.md`, `СТАТУС.md` и конец `ЖУРНАЛ.md`. Остальные
   страницы — по просьбе нейросети.
3. Нейросеть **возвращает правки текстом**: какой файл, что добавить или заменить. Вы переносите их
   в файлы сами. Это медленнее, но методика работает так же.
4. Большой источник (стенограмма на час) отдавайте на приём один раз. Дальше храните и загружайте
   только его резюме — это главная экономия.

### В. Несколько нейросетей в одном проекте

- **Писатель один.** Живые страницы, `INDEX.md` и `ЖУРНАЛ.md` правит одна ведущая нейросеть
  или один человек. Остальные читают и возвращают результат текстом — иначе страницы разъедутся.
- Задание другой модели оформляйте по [templates/ЗАДАНИЕ.md](templates/ЗАДАНИЕ.md):
  контекст, критерий успеха, шаги, входные файлы, правила, формат ответа.
- Вторая модель полезна как **проверяющий**: «найди, где в этом плане ошибка», «что здесь не доказано».

## 10. Автономные циклы — осторожно

Агента можно оставить работать без человека, например на ночь, если у задачи есть **измеримый
результат**: доля правильных ответов бота на наборе эталонных вопросов, число пройденных тестов.
Цикл запускается только по файлу [templates/ПРОГРАММА.md](templates/ПРОГРАММА.md), где записаны:
цель; одна метрика; что можно менять; что **нельзя трогать**; бюджет; правило «лучше — оставить,
хуже — откатить»; журнал попыток.

**Никогда** — на боевых системах, на данных заказчика, с отправкой писем и сообщений наружу, с деньгами.

## 11. Чего не делать

- Не складывать весь проект в один огромный файл «контекста». Оглавление и короткие страницы работают
  лучше и дешевле.
- Не верить отчётам «готово на 100%» без ссылок на проверку.
- Не мерить работу количеством: «500 функций», «10 000 автоматизаций». Считается проверенный результат.
- Не давать нейросети править источники и старые записи журнала.
- **Не хранить пароли, ключи и токены в папке проекта** — ни в файлах, ни в журнале, ни в чате.
  Держите их в менеджере паролей или отдельном хранилище вне синхронизируемых папок.
- Не разрешать агенту «улучшать заодно» то, о чём его не просили.

## 12. Быстрый старт за 15 минут

1. Скопируйте [templates/](templates) в папку проекта. Создайте пустую папку `Источники/_резюме/`.
2. Заполните в `AGENTS.md` название проекта, цель и границы. В `ПЛАН.md` заполните устав.
3. Положите в `Источники/` всё, что уже есть по проекту: переписку, стенограммы, ТЗ.
4. Попросите нейросеть по [prompts/1-приём.md](prompts/1-приём.md) принять источники по одному.
5. Проверьте `INDEX.md`, `СТАТУС.md`, `ВОПРОСЫ.md`. Ответьте на вопросы по одному.
6. С этого момента каждая сессия начинается с [prompts/0-начало-сессии.md](prompts/0-начало-сессии.md),
   а раз в неделю проводится сверка.
